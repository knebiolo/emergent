Plan (detailed)
------------------
- Goal: Split src/emergent/salmon_abm/sockeye.py into maintainable modules and preserve backward compatibility.

- Files to create:
  - utils.py: helpers (array helpers, geo_to_pixel, pixel_to_geo, standardize_shape, determine_slices_*, calculate_front_masks, interpolation helpers).
  - io.py: environment import, HDF5 helpers, movie_maker, output_excel, raster/shapefile helpers, longitudinal_import, enviro_import.
  - pid.py: PID_controller, interp_PID, PID_func and PID helpers.
  - simulation.py: simulation class, constructor orchestration, run/timestep/close and public API for running simulations.
  - movement.py: movement class, odometer, initial_swim_speed, initial_heading.
  - behavior.py: behavior class and behavior methods.
  - fatigue.py: fatigue class and fatigue computations.
  - summary.py: summary class and reporting methods.
  - compat (sockeye.py wrapper): re-export public symbols to preserve existing imports.

- Public API per module (high level):
  - utils: geo_to_pixel, pixel_to_geo, standardize_shape, calculate_front_masks, determine_slices_from_*
  - io: enviro_import(path, kind), longitudinal_import(path), write_hdf5_initial(state, path), movie_maker(...), output_excel(records, model_dir, model_name)
  - pid: PID_controller(n_agents, k_p, k_i, k_d, tau_d)
  - simulation: simulation(...), run(), timestep()
  - movement/behavior/fatigue: classes or functions composed by `simulation`.

- Import changes:
  - Centralize heavy dependencies where reasonable. Use relative imports (from .utils import ...).
  - Preserve function signatures for public-facing APIs.

- Compatibility & non-destructive strategy:
  - Keep original sockeye.py as a thin wrapper that re-exports from new modules.
  - Add __all__ lists to new modules to make exports explicit.

- Testing strategy:
  - Unit tests for pure helpers (utils, pid) first.
  - Run targeted pytest for tests that touch changed areas.

- Risks / Blockers:
  - Tight coupling between inner classes and `simulation` internals may require careful refactor.
  - Module-level constants (current_dir, rcParams, FFmpeg path) must be centralized or passed in.
  - GPU conditional imports and environment-specific paths may need consolidation.

- Acceptance criteria:
  - New module files created and importable.
  - Backwards-compatible imports from `sockeye.py` continue to work.
  - Targeted tests for modified areas pass.
